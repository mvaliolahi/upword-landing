آموزش زبان انگلیسی (دورهٔ ۹۰ درسی) · درس ۵۴ از ۹۰

گیت به انگلیسی؛ commit, pull request و merge بدون تصادف

🗓 ۲ آبان ۱۴۰۵ ⏱ ۶ دقیقه مطالعه ✍ تیم آپ‌ورد
⚡ پاسخ کوتاه

گیت، گرامرِ کارِ تیمی است و جمله‌هایش ثابت‌اند: I'll create a branch, open a PR, address the comments, and merge. سخت‌ترین لحظه‌اش هم جمله دارد: "I have a merge conflict — could you help me resolve it?" این درس، دیکشنریِ گفتاریِ گیت را می‌سازد — از clone تا squash.

اگر تا حالا گیت را تنها استفاده می‌کردی، جمله‌هایش را «نمی‌دیدتی»؛ اما در تیم، گیت زنده حرف می‌زند: در اسلک، در استندآپ، در ریلویو. و اشتباه‌های گیت — کنفلیکت، فورس‌پوش، ری‌بِیسِ اشتباه — وقتی زبان نداشته باشی، به‌جای «پشیمانیِ فنی» به «وحشتِ زبانی» تبدیل می‌شوند.

این درس فقط لحنِ گفتاری را می‌دهد (دستورِ گیت که خودت بلدی یا help می‌گیرد): فعلِ درست برای هر عمل، اسم‌های محاوره‌ای (PR, repo, main), و جمله‌های پیش apologize. ریلویویِ کامل، درسِ بعدی است؛ این درس زیرساختِ گفتاری‌اش.

فعل‌های گیت؛ دیکشنریِ روزانه

عمل فعلِ گفتاری جمله
repo را کپی کردن clone Clone the repo and run the setup script.
شاخهٔ جدید branch off / create a branch I'll branch off main for this feature.
ثبتِ تغییر commit Committed the fix — small, focused commit.
گرفتنِ تغییرِ دیگران pull Pull main before you start — it moved.
فرستادن push Just pushed — can you take a look?
درخواستِ ادغام open a PR I opened a PR — it's ready for review.
دیدگاه‌ها را اعمال‌کردن address the comments Addressed your comments and pushed again.
ادغام merge Merged! The feature is on staging.
ادغامِ فشرده squash and merge Let's squash — 14 commits is too noisy.
برگشتن revert / roll back We reverted the release — back to normal.

اسم‌های محاوره: repo (ریپازیتوری), main (شاخهٔ اصلی — قبلاً master), PR (pull request; در GitLab: MR = merge request), diff (اختلافِ نسخه‌ها), conflict (تعارض), commit history (تاریخچه). و ادبِ فنی: اسمِ شاخه را معنادار بگذار و در پیامِ اسلک بگو: "PR is up: feature/checkout-v2 — small one, ~200 lines."

Pull Request؛ پستِ مرکزیِ گفتگو

قالبِ توضیحِ PR (که آدم‌ها را دوستت می‌کند): What & Why: "Adds retry logic to the payment client." · How: "Uses exponential backoff, capped at 5 tries." · Testing: "Covered with unit tests; deployed to staging and ran a manual charge." · Notes: "Diff looks big, but half of it is a generated file." — همین چهار خط، نصفِ سوال‌های ریلویور را قبل از پرسیدن جواب می‌دهد. و درخواستِ ریلویوی محترمانه: "Could you review when you get a chance? Not urgent — by EOD would be great."

PR is up: it moves the email sender to a background job. Small blast radius, tests included. Let me know if anything looks off!PR اومد: ایمیل‌فرست رو بردیم روی jobِ پس‌زمینه. دامنهٔ اثرِ کوچیک، تست هم داره. اگه چیزی مشکوک بود خبر کن!

وقتی خراب شد؛ جمله‌های پیش‌آپدیجیِ گیت

کنفلیکت: "I have a merge conflict with main — could you pair with me for five minutes? I don't want to break the release." فورس‌پوشِ اشتباه: "Heads-up: I force-pushed to the shared branch by accident — I'm fixing it now, sorry!" (Heads-up = توجه — کلمهٔ نجاتِ اعلامِ خرابی) برگشتنِ فوری: "Can we revert the last commit on main? It broke the build." لاگِ گم‌شده: "Does anyone know where yesterday's commits went? I can't find the branch." — همهٔ این جمله‌ها با آرامشِ صریح گفته می‌شوند؛ در فرهنگِ تیم‌های سالم، اعلامِ سریعِ خرابی، امتیاز است: "I'd rather flag it early than let it spread."

🔑 جمع‌بندی این درس

گیت گفتاری: branch off / commit / pull / push / open a PR / address comments / squash and merge / revert. PR با چهار خطِ What-How-Testing-Notes. خرابی با heads-up + sorry + درخواستِ help. جملهٔ امنیتیِ هر جا: "I don't want to break the release" — نشانِ مهندسِ مسئول، در هر زبانی.

پرسش‌های رایج

«It works on my machine» را جدی بگویم؟
به‌عنوان شوخی، آره — به‌عنوان استدلال، هرگز! نسخهٔ حرفه‌ای: "It runs locally, but the CI environment is different — let me check the config." (لوکال اجرا می‌شه ولی محیطِ CI فرق داره — بذار کانفیگ رو چک کنم.) جملهٔ شوخی‌اش را همه می‌دانند و می‌خندند؛ جملهٔ جدی‌اش را مهندس‌ها می‌پسندند.
Rebase و merge در گفتار چطور جدا می‌شوند؟
هر دو، آوردنِ تغییرِ شاخه‌ها به هم است؛ فرقِ فنی: merge تاریخچه را حفظ می‌کند، rebase خطی می‌سازد. در گفتار: "Should we rebase on main or just merge?" (ری‌بیس کنیم روی main یا فقط مِرج؟) و قاعدهٔ محترمانهٔ تیم‌ها: **نprecher هرگز روی شاخهٔ اشتراکی rebase نکن** — جمله‌اش اگر لازم شد: "Rebasing the shared branch would rewrite history — let's merge instead." (تاریخچه رو عوض می‌کنه — مِرج کنیم.)

انگلیسی را همین امروز در گوشی‌ات تمرین کن

واژه‌های این درس را هر جا که دیدی با منوی «ذخیره در آپ‌ورد» به فلش‌کارت‌هایت اضافه کن؛ الگوریتم مرور فاصله‌دار سرِ موعد یادآوری‌شان می‌کند، تلفظ‌شان را می‌شنوی و در مکالمهٔ هوش مصنوعی همان‌جا که لازم است استفاده‌شان می‌کنی.

کدریویو؛ دادنِ بازخوردِ فنی و گرفتنش بدونِ زخم

🗓 ۲ آبان ۱۴۰۵ ⏱ ۱۰ دقیقه مطالعه ✍ تیم آپ‌ورد
⚡ پاسخ کوتاه

کدریویو دو نیمهٔ جداشدنی ندارد — دادن و گرفتنِ نظرِ فنی، هر دو با قالب می‌آیند. دادن: دسته‌بندیِ کامنت‌ها (nit / suggestion / blocking) و سوال‌بستن به‌جای حکم (Would you consider…?). گرفتن: thanks, good catch — و جداکردنِ «کد» از «خود».

کدریویو، حساس‌ترین مکالمهٔ فنی است: می‌خواهی به همکارت بگویی کدش بد است، بدونِ این‌که بگویی خودش بد است — و برعکس، بخوری «این غلط است» را بدونِ دفاعِ شخصی. فرهنگِ تیم‌های انگلیسی‌زبانِ سالم برای همین، قالب‌های دقیقی دارد؛ قالب‌ها هم مؤدب‌اند هم کارآمد.

برای زبانِ دوم یک خبرِ خوب: کامنتِ ریلویو، مکالمهٔ کوتاهِ نوشتاری است — زمانِ فکر دارد. همین درس را نه فقط بخوان، بلکه template کن؛ اولین ریلویوی جدی‌ات، از دل همین قالب‌ها بیرون می‌آید.

دادنِ کامنت؛ سه درجه و دو قالب

درجه واژه جملهٔ نمونه
اصلاحِ ضروری blocking / must-fix Blocking: this breaks on empty input — we need a guard clause.
پیشنهاد suggestion / could consider Suggestion: we could extract this into a helper — up to you.
جزئی nit (nitpick) Nit: trailing space here. Not blocking.
ستایش praise / this is nice This is a really clean solution — learned something!
سوال question Question: why array over set here? Genuine curiosity.

دو قالبِ طلاییِ نرم‌کردن: ۱) سوال به‌جای حکم: نهِ «This is wrong» — که «Would you consider using a set here? Lookups would be O(1).» ۲) «ما» به‌جای «تو»: «What if we extracted the validation into its own function?» — «ما»، کامنت را از امتحانِ شخصی به تصمیمِ مشترک می‌برد. و قانونِ «praise در جا»: اگر چیزی خوب بود، همان لحظه بنویس — ریلویو فقط شکارِ اشکال نیست.

Nit: could we name this `retryCount` instead of `n`? Future-us will thank us.جزئی: می‌شه اسمش retryCount باشه نه n؟ خودِ آینده‌مون ممنون می‌شه.

گرفتنِ کامنت؛ سه پاسخِ حرفه‌ای

۱) پذیرشِ گرم: "Good catch — fixing now." (دقتِ خوبی بود — همین الان درستش می‌کنم) ۲) توضیح + بازگشایی: "Fair point. I kept it sync because the caller needs the value immediately — but I'm open if you see a cleaner way." ۳) مخالفتِ مستند: "I see it differently — with the new cache, the extra query costs almost nothing. Happy to discuss on a call if you're not convinced." — هر سه: کوتاه، بی‌حالتیِ دفاعی، و برنده. قاعدهٔ طلایی: هر کامنت را یک نظرِ فنی ببین نه حکمِ شخصی — جملهٔ یادگاریِ صنعت: "Review the code, not the coder."

Thanks for the thorough review! Addressed everything except the last point — added a comment in the PR explaining why.ممنون بابت ریلویوی کامل! همه رو اعمال کردم جز آخرین نکته — تو PR توضیحش رو نوشتم.

جریانِ ریلویو؛ درخواست تا merge

زبانِ جریان: "Could you take a look when you get a chance?" (درخواست) · "Left a few comments — nothing blocking." (جوابِ ریلویور) · "Pushed the changes — PTAL." (اعمال شد؛ PTAL = please take another look — مخففِ محبوبِ گیت‌هاب) · "LGTM!" (looks good to me — یعنی تأیید؛ سه حرفِ شیرینِ هر PR) · "LGTM with nits." (تأیید — با همین جزئی‌های کوچیک). ادبِ زمان: ریلویوِ PRِ دیگران را همان روزی که می‌خواهی خودت ریلویو شوی بده — اقتصادِ متقابلِ تیم‌های سالم است.

گرامرِ عمیق‌تر: مودالِ ریلویو — should و could و نرمیِ شرطی

ریلویو، زبانِ مودال‌های مشورتی است: should (پیشنهادِ قوی: this should be async), could (گزینه: we could extract a helper), might (احتمال: this might break on empty input) — و نرم‌ترینِ همه، شرطیِ دوم: If this were a public API, I'd rename it (اگر API عمومی بود، اسمش رو عوض می‌کردم) — were/'d، فرمِ مؤدبانهٔ نقدِ فرضی! و برای درجه‌گذاریِ نظری به لحنِ نوشتاری: Blocking: (بلاک‌کننده), Nit: (جزئی), Question: (سوال) — سه برچسبِ اولِ کامنت، ریلویو را از گفتگو به سندِ تصمیم می‌برد.

Question: do we need this loop at all? If it were just a lookup, a hash map would do the job in one pass — happy to be wrong here!سوال: اصلاً به این حلقه نیاز داریم؟ اگه فقط جستجو بود، یه هش‌مپ توی یه پاس کافیه — خوشحال می‌شم اشتباه کرده باشم!

گفتگو: بحثِ ریلویو در thread و جمع‌بندی

Reviewer: Blocking — this swallows the error, and we just got burned by that in payments. — You: Fair. I'll log and rethrow. — Reviewer: That's all I wanted.ریلویوئر: بلاک — این خطا رو قورت می‌ده، و تازه تو پرداخت از همین سوخته بودیم. — تو: درسته. لاگ می‌کنم و دوباره می‌اندازمش. — ریلویوئر: همین می‌خواستم.
Reviewer: Nit: this name, `data2`… future-us will suffer. — You: Ha! Renamed to `pricingSnapshot`. — Reviewer: LGTM with that one nit.ریلویوئر: جزئی — این اسم، data2… خودِ آیندهٔ ما زجر می‌کشه. — تو: ها! به pricingSnapshot تغییرش دادم. — ریلویوئر: LGTM با همین جزئی.
You: Pushed — PTAL. And thanks for the burn-mark story, honestly — context like that is why I'd rather have reviews than ship blind. — Reviewer: Same. That's the whole job.تو: پوش شد — یه نگاه دیگه. و ممنون از داستانِ سوختگی — زمینه‌ی این‌جوری دلیلِ ترجیحِ ریلویو به شِپِ کوره. — ریلویوئر: منم. کلِ کار همینه.

نکات مکالمهٔ واقعی که کتاب‌ها کم می‌گویند

  • Happy to be wrong — پایانِ کامنتِ نظر-محور: «happy to be wrong here» — علامتِ آگاهیِ تیمی؛ نظر می‌دهی، جنگ نمی‌کنی.
  • پاسخِ بلند ننویس — پاسخِ کامنت: یک-دو خط یا یک commit. بحثِ طولانی در thread = جلسهٔ پنهان — بردارش به تماس.
  • رایِ نهایی را با برچسب بده — پایانِ ریلویو: «LGTM» یا «LGTM with nits» — ابهامِ «خوبه ولی…»، مرج را معلق می‌کند.
🔑 جمع‌بندی این درس

دادن: درجه‌گذاری (blocking / suggestion / nit / praise) + سوال به‌جای حکم (Would you consider…?) + «we» به‌جای «you». گرفتن: Good catch / Fair point / مخالفتِ مستند با پیشنهادِ تماس. جریان: PTAL و LGTM — دو مخففِ دنیای ریلویو. و یادت باشد: کامنت، هدیهٔ فنی است؛ قالبش را همین درس داده.

پرسش‌های رایج

ریلویور تندگوی است و کامنت‌ها زخم‌اند — چه کنم؟
سه پله: ۱) قالب را از خودت نگیر: «This is wrong» را به «رو کد نظر می‌ده» ترجمه کن — و جوابِ سردِ حرفه‌ای بده (بالاتر). ۲) اگر لحنِ واقعاً بی‌ادبانه تکرار شد، خصوصی و آرام: **"Hey, your technical points are always solid — the tone sometimes makes it hard to process. Could we keep it a bit softer?"** ۳) اگر ادامه کرد، مدیر/لید را در جریان بگذار — تیمِ سالم، تیکتِ لحن هم دارد. اما ۹۰٪ موارد، همان پلهٔ یک کافی است: جوابِ آرامِ بی‌دفاعی، خودش لحن را بعد از دو-سه ریلویو نرم می‌کند.
چطور ریلویوگرِ خوبی شوم وقتی جونیورم؟
سه امانتِ ریلویوگرِ جونیور: **۱) سوال بپرس** — سوالِ واقعی، کامنتِ محترم است: «Curious — why not use the standard library here?» **۲) چیزی که یاد گرفتی را بگو**: «TIL you can do this with pattern matching — nice.» **۳) تست و UX را چک کن** — چشمِ تازه، خطاهایی می‌بیند که چشمِ خبره عادت کرده است. جونیورِ ریلویوگرِ فعال، سریع‌ترین مسیرِ ارتقای فنی-اجتماعی است.

انگلیسی را همین امروز در گوشی‌ات تمرین کن

واژه‌های این درس را هر جا که دیدی با منوی «ذخیره در آپ‌ورد» به فلش‌کارت‌هایت اضافه کن؛ الگوریتم مرور فاصله‌دار سرِ موعد یادآوری‌شان می‌کند، تلفظ‌شان را می‌شنوی و در مکالمهٔ هوش مصنوعی همان‌جا که لازم است استفاده‌شان می‌کنی.

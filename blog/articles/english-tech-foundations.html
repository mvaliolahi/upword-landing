واژگانِ فنیِ پایه؛ کامپیوتر، اینترنت و ابر

🗓 ۲ آبان ۱۴۰۵ ⏱ ۱۵ دقیقه مطالعه ✍ تیم آپ‌ورد
⚡ پاسخ کوتاه

قبل از جلسه و کد، باید «طبقهٔ واژه‌های فنی» محکم باشد: hardware/software, network, server, cloud, database, API. و مهم‌تر از معنا، تلفظِ درست است — Git با «گیتِ» ساده, Linux «لینوکس», suite «سوئیت نه سویت». این درس، پایهٔ واژگانیِ فاز ۴ است.

برنامه‌نویس‌ها فکر می‌کنند چون «کد» می‌زنند، انگلیسیِ فنی بلدند — و نصفه درست است: واژه‌ها را «دیدنِ» با واژه‌ها را «شنیدن و گفتنِ» فرق دارد. در استندآپ، تلفظِ غلطِ یک کلمهٔ فنیِ رایج (مثل «سِقورِتی» برای security) اعتمادِ فنی را بی‌دلیل می‌شکند؛ و برعکس، تلفظِ درستِ همان ده-پانزده کلمه، ورودِ تو به گفتارِ تیم را نرم می‌کند.

این درس دِصلِ است: مفاهیمِ پایه به ترتیبِ لایه‌ها (دستگاه ← شبکه ← سرور ← ابر) + جدولِ تلفظِ خائن‌ها. همهٔ درس‌های فاز ۴ از همین طبقه بالا می‌روند.

لایه‌ها؛ از دستگاه تا ابر

لایه واژه‌ها یک جمله
دستگاه hardware, CPU, memory (RAM), storage, screen My laptop has 16 gigs of RAM.
نرم‌افزار software, app, program, operating system (OS) Which OS are you on — Mac or Linux?
شبکه network, Wi-Fi, connection, bandwidth, latency The latency to the EU server is too high.
سرور server, host, port, request, response The server is not responding on port 8080.
ابر cloud, instance, region, bucket, scaling We moved everything to the cloud last year.
داده database, table, query, backup, migration The migration finished — the database is live.
رابط API, endpoint, token, payload The API returns a 401 — the token expired.

جمله‌های توصیفیِ فنی که بارها لازم می‌شوند: "It works on my machine" (روی سیستمِ من کار می‌کنه — شوخیِ مقدسِ صنعت!) · "The app is down" (اپ down است — پایین است/کار نمی‌کند؛ خلافش up) · "It's a server-side issue" (مشکل سمپِ سرور است) · "Let me check the logs" (لاگ‌ها را چک کنم). up/down و frontend/backend و client-side/server-side — زبانِ فنی با این جفت‌ها فکر می‌کند.

قاعدهٔ طلاییِ تلفظِ فنی: واژهٔ فنی، شهروندِ زبانیِ خودش است — با انگلیسی تلفظ می‌شود نه با املایش فرانسوی/آلمانی. اگر شک داری، کلمه را به آپورد اضافه کن و صدای en-US را بشنو؛ دو-سه بار تکرار کن. سرمایه‌گذاریِ ده‌دقیقه‌ای که در اولین جلسه‌ت صدا می‌زند.

وصفِ مسئله؛ سه قالبِ فنیِ روزمره

۱) گزارشِ خام: "The build fails on the CI — here's the log." · ۲) گزارشِ دقیق‌تر (۴۳۲۱): "The checkout API returns a 500 when the cart has more than 10 items — works fine below that." (چه‌زمان/کِی + چه‌ رفتار + کجا درست است — فرمولِ توصیفِ باگ که در درس ۵۷ کامل می‌شود) · ۳) درخواستِ دسترسی: "Could you add me to the staging cluster? I need it for the load test." با همین سه قالب + جدولِ تلفظ، فاز ۴ باز می‌شود.

گرامرِ عمیق‌تر: زبانِ فنیِ صفت‌محور و مخفف‌ها

توصیفِ فنی با صفت‌های مرکب می‌آید: a load-balanced setup (راه‌اندازیِ بار-موزع), a fault-tolerant system (خطا-پذیر — یعنی خطا را تحمل می‌کند), an event-driven architecture (رویداد-محور), a cloud-native app (ابر-بومی). مخفف‌های گفتاری: API (آ-پی-آی — سه حرف!), DB (دیتابیس), CI/CD (سی-آی-سی‌دی), env (environment — محیط), repo, PR, LGTM. و صفتِ کلیدیِ مقیاس: scalable (مقیاس‌پذیر) در برابر scaled — «It scales» (مقیاس می‌گیره) فعلِ محبوبِ گفتارِ فنی است.

We're moving to an event-driven, cloud-native setup — the old monolith doesn't scale the way the traffic demands now.داریم می‌ریم سمتِ راه‌اندازیِ رویداد-محور و ابر-بومی — مونولیتِ قدیمی مثلِ ترافیکی که الان می‌خواد مقیاس نمی‌گیره.

گفتگو: معرفیِ معماری به همکارِ تازه

اشتباه‌های رایجِ فارسی‌زبان‌ها در همین درس

این بخش را با یک قرارداد بخوان: هر ❌ یعنی «مغزِ فارسی‌زبانت این را می‌سازد و طبیعی است»، و هر ✅ یعنی «این همان چیزی است که گیرندهٔ انگلیسی‌زبان می‌شنود». خطاها اثرِ مستقیمِ ترجمهٔ ذهنیِ فارسی به انگلیسی‌اند؛ با هر جفت بلند تکرار کن تا شکلِ درست در گوشت نشست کند.

❌ The server is not answering.❌ «پاسخ نمی‌دهد» را مغز با answering می‌سازد؛ اما در زبانِ فنی، سرورها respond می‌کنند نه جواب می‌دهند. فعلِ درست نصفِ گزارشِ فنی است: "The server isn't responding on port 8080" کلِ جملهٔ استاندارد است.
✅ The server is not responding.✅ شکل درست را دو بار بلند بگو؛ حالا یک بار در یک جملهٔ خودت.
❌ My laptop has 16 RAM.❌ «رمِ ۱۶» را بدونِ واحد می‌گوییم؛ اما گفتارِ فنی واحدِ کوتاه می‌خواهد: 16 gigs of RAM. عددِ بی‌واحد در جلسهٔ فنی یعنی عددِ بی‌قد — واحدِ درست، اعتبارِ فنی می‌آورد.
✅ My laptop has 16 gigs of RAM.✅ شکل درست را دو بار بلند بگو؛ حالا یک بار در یک جملهٔ خودت.
❌ I cleared the cash memory.❌ واژهٔ cache را گوشِ فارسی «کَش» می‌شنود و مغز، cash (پولِ نقد) را می‌نویسد؛ اما حافظهٔ موقتِ سرورها cache است — دو هم‌تلفظِ خائن. در چت و داک، همین یک حرفِ جاافتاده، اعتبارِ فنی‌ات را لو می‌دهد.

تمرین‌های این درس — چهار قدم، بی‌عجله

واژگانِ فنی را با جملهٔ کامل تمرین کن؛ پاسخ‌ها را با تلفظِ درست و بلند بگو.

  1. جای خالی: «The app ___ (is / has been) down since 9 a.m. — I'm checking the logs.»
  2. اصلاح کن: "My laptop has 16 RAM and the server is not answering. I cleared the cash but nothing."
  3. گزارشِ دقیقِ باگ را با فرمولِ درس بساز: «وقتی سبدِ خرید از ۱۰ آیتم بیشتر شود، API تسویه ۵۰۰ برمی‌گرداند؛ زیرِ آن درست کار می‌کند.»
  4. چهار جفتِ خائنِ فنی را کامل کن: up ↔ ___، frontend ↔ ___، client-side ↔ ___، request ↔ ___.

پاسخ تمرین‌ها — اول خودت جواب بده، بعد باز کن

پاسخ تمرین ۱
has been — "The app has been down since 9 a.m." گزارشِ وضعیتِ ادامه‌دار، Present Perfect می‌خواهد؛ همین جمله، قالبِ ثابتِ اسلک و صفحهٔ status است.
پاسخ تمرین ۲
"My laptop has 16 gigs of RAM and the server isn't responding. I cleared the cache, but nothing changed." — سه قالبِ درس یک‌جا: واحدِ gigs، فعلِ responding و cache بی‌غلطِ هم‌تلفظ‌ها.
پاسخ تمرین ۳
"The checkout API returns a 500 when the cart has more than 10 items — it works fine below that." — چه‌زمان + چه‌رفتار + کجا درست است؛ سه‌بندی‌ای که گزارشِ باگ را از غرغر به مهندسی می‌برد.
پاسخ تمرین ۴
down (the app is down) · backend · server-side · response — زبانِ فنی با جفت‌ضدهایش فکر می‌کند؛ چهار جفت را قفل کن، نصفِ گفتارِ استندآپ آماده است.

چالشِ امروز

🎯 پنج واژه‌ای را که تا امروز غلط تلفظ می‌کردی — مثلِ cache، queue، schema، suite، Linux — با صدای بلند و درست ده‌بار بگو؛ تلفظِ درست، اولین دست‌دادنِ فنیِ توست.

نکات مکالمهٔ واقعی که کتاب‌ها کم می‌گویند

  • نقشه را خودت بکش — هر معماری را که برایت توضیح دادند، خودت بازکش کن و تأیید بگیر — نقاشیِ دوم، فهمِ اول را می‌سازد.
  • مخفف را بلند بگو — مخفف‌ها فقط نوشتاری نیستند: API و DB و CI/CD تلفظِ حروفی دارند — با آپورد صدای هر یک را بشنو.
  • It scales را جا بینداز — «It scales» و «it doesn't scale» — دو جمله‌ای که در هر بحثِ معماری می‌شنوی؛ ترجمه‌شان در ذهنت آماده باشد.
🔑 جمع‌بندی این درس

لایه‌های واژه: دستگاه (RAM, storage) ← نرم‌افزار (OS, app) ← شبکه (latency, bandwidth) ← سرور (port, request) ← ابر (instance, region) ← داده (query, migration) ← API (endpoint, token). تلفظ‌های خائن را جدول کن: Git=گیت, cache=کش, queue=کیو, schema=اسکِما. و up/down و client/server — زبانِ فنی با جفت‌ضدهایش حرف می‌زند.

پرسش‌های رایج

«gig» و «meg» و «k» یعنی چه؟
کوتاه‌هایِ واحد: gig = gigabyte (گیگ), meg = megabyte, k = kilobyte. جمله: "How much RAM do you have? — 16 gigs." فایل: "The video is like 200 megs." و مهم‌تر: در گفتارِ فنی، «Kubernetes» را k8s می‌نویسند اما «کوبرنتیز» می‌گویند — کوتاه‌نویسی فقط نوشتاری است (i18n هم همین‌طور: در گفتار internationalization).
واژه‌های فارسی‌شده‌ای که نباید استفاده کنم؟
تلفظِ بومی‌شده در گفتار با خودتان آزاد است؛ در جلسهٔ بین‌المللی، نسخهٔ انگلیسی درست احترام است: «فِریم‌ورکِ» نه — framework؛ «دِپلوی» می‌گویند (deploy قابل‌قبول است) اما «استوریجِ» نه — storage. قاعده: هر واژه که در متنِ فنی می‌نویسی، تلفظِ انگلیسی‌اش را هم یاد بگیر — آپورد، مربیِ شنیداریِ همین لایه است.

انگلیسی را همین امروز در گوشی‌ات تمرین کن

واژه‌های این درس را هر جا که دیدی با منوی «ذخیره در آپ‌ورد» به فلش‌کارت‌هایت اضافه کن؛ الگوریتم مرور فاصله‌دار سرِ موعد یادآوری‌شان می‌کند، تلفظ‌شان را می‌شنوی و در مکالمهٔ هوش مصنوعی همان‌جا که لازم است استفاده‌شان می‌کنی.
